2. **Divisão de Tarefas:** Sempre divida programações extensas em tarefas e subtarefas incrementais e testáveis.
3. **Registro de Alterações:** Mantenha e atualize continuamente um arquivo `backlog.md` na raiz do repositório, registrando todas as funcionalidades implementadas, corrigidas ou alteradas.

## 🛠️ Stack Tecnológica e Bibliotecas
- **Repositório:** GitHub
- **Backend & Banco de Dados:** Supabase (conectado via API REST / Cliente JS via CDN)
- **Frontend:** HTML5, CSS3, JavaScript Vanilla
- **Bibliotecas Permitidas (via CDN):**
  - `@supabase/supabase-js` (para comunicação simplificada com a API do Supabase)
  - `Lucide Icons` ou `Font Awesome` (para ícones vetoriais; proibido o uso de emojis na interface)

## 🎨 Interface e Experiência do Usuário (UI/UX)
- **Público-Alvo:** Uso exclusivo em **Tablets e Desktop** (layout responsivo com foco em telas médias/grandes).
- **Estilo:** Design limpo (Clean UI), fundo predominantemente branco (`#FFFFFF`), alta legibilidade e contraste.
- **Ícones:** Uso estrito de biblioteca de ícones vetoriais (ex: Lucide) para ações, status e navegabilidade.
- **Recursos Nativos:** Uso de API de Câmera (`navigator.mediaDevices.getUserMedia`) para validação facial/liveness no tablet, e Geolocalização (`navigator.geolocation`) para validação de raio (Geofencing) no aplicativo móvel/web.

## 📐 Regras de Negócio e Requisitos do Sistema

### 1. Perfis e Tolerâncias por Cargo
- **Cozinha (Pizzaiolo, Auxiliares):** Tolerância máxima de 5 minutos na entrada. Atrasos disparam alertas no painel do gerente.
- **Entregadores (Motoboys):** Horário flexível na saída. Se houver pedido em rota de entrega próximo ao horário de término, o tempo adicional é classificado automaticamente como `HORA_EXTRA_ENTREGA`.
- **Atendimento e Caixa:** Tolerância de 10 minutos. O registro de saída é **condicionado** à confirmação de fechamento do caixa no sistema de vendas.
- **Exceções/Emergências:** O registro de saída travado por caixa aberto pode ser liberado por override do gerente ou marcado com a flag `SAIDA_FORCADA_EMERGENCIA` para posterior justificativa com atestado/comprovante.

### 2. Jornada Noturna (Virada de Meia-Noite)
- A **Data de Referência** do turno é definida no momento do registro da `ENTRADA`.
- Batidas de saída ocorridas após a meia-noite (ex: 02:00 do dia seguinte) devem ser vinculadas à data de referência da entrada correspondente.

### 3. Validação e Antifraude
- **Dispositivo Fixo (Tablet da Pizzaria):** Registro exige captura facial e confirmação de horário obtido via servidor NTP/Supabase.
- **Dispositivo Móvel (Entregador):** Validação de raio de alcance via GPS (Geofencing) e checagem de IP/Rede local.

## 🔌 Endpoints e Integração com Supabase API
O agente de IA deve implementar as rotas/funções de serviço utilizando o cliente JS do Supabase:

1. `POST /ponto/registrar`: Valida horário, cargo, tolerância e registra a batida com hash único do comprovante.
2. `GET /ponto/comprovante/:hash`: Consulta a autenticidade de um ticket emitido.
3. `POST /ocorrencias/justificar`: Anexa justificativa e comprovantes para atrasos, faltas ou saídas forçadas.
4. `GET /funcionarios/:id/espelho`: Retorna o histórico de registros e inconsistências consolidadas.
